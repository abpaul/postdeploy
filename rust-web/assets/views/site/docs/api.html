Authentication

Send an API key or an OAuth access token as a bearer token. The key's scopes decide which endpoints answer.

curl -H "Authorization: Bearer $POSTDEPLOY_API_KEY" \
  {{ plan.public_url }}/api/orgs/ORG_ID/issues

Some endpoints, such as creating and revoking API keys, need a signed-in browser session. The endpoint lists show which. See API keys.

Record a deployment

Call this from CI with a key that has deployments:write. That scope records deployments only.

curl -X POST "{{ plan.public_url }}/api/orgs/ORG_ID/projects/PROJECT_ID/deployments" \
  -H "Authorization: Bearer $POSTDEPLOY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"version": "web@1.4.2", "environment": "production", "commit_sha": "COMMIT_SHA"}'

Sending the same version, environment and deployed_at again returns the stored deployment. Without deployed_at, PostDeploy uses the time it receives the request.

Lists and pages

Project and source lists return 25 items by default and 100 at most. Pass limit to change it, and pass the returned next as after for the next page. Issue, log and deployment lists return next for before.

Errors and limits

Errors are JSON, for example {"error": "invalid_pagination"}. Log searches and error context share one query budget per organization. Over it, the API answers 429 rate_limited with Retry-After.
