Your agent works from whatever you paste.

When production breaks, you copy a stack trace from one tab, search logs in another and check which deploy went out. Then you paste it into the chat. The agent sees only what you remembered to copy.

One tool call returns the evidence.

get_error_context returns one error event with its stack, the deployment that was live, and up to 50 logs that share its trace ID. Without a trace ID it matches on request ID, then on service and release, and says which match it used. Every result is size-limited and says when it was cut.

How it works

  1. Change one DSN.

    Point your Sentry SDK at a PostDeploy DSN. Node.js sends errors and logs. Python, Ruby and Elixir send errors. A test event checks the path before you deploy. Read the quickstart.

  2. Connect your agent.

    claude mcp add --transport http postdeploy {{ plan.mcp_url }}
    codex mcp add postdeploy --url {{ plan.mcp_url }}

    Your browser opens. You choose the organization and the access. New connections can only read.

  3. Ask what broke.

    Your agent lists open issues, reads the error context and compares error rates before and after the last deployment.

Capabilities

  • Keep your Sentry SDK.

    PostDeploy accepts a standard DSN. To leave, change the DSN back.

  • Errors linked to logs.

    Matched by trace ID or request ID, and labeled with how they matched.

  • Deployments from CI.

    One HTTP call per deploy. Compare error rates before and after it.

  • Least access by default.

    Read-only connections, scopes you grant, keys that expire in 30 days. Revoke any of them from the dashboard.
