## MANDATORY — Response shape (ADHD)

These rules are not style preferences. The developer has ADHD. Output that ignores them is unusable and counts as a failed task.

They apply to every agent: the main loop, every subagent, and every skill. If you spawn a subagent, put these rules in its prompt. If you receive a task as a subagent, apply them to your report.

- Lead with the next action — a command, path, or snippet on the first line. No preamble.
- Number multi-step work. One bounded action per step. Use the fewest steps that still work.
- Restate state every turn ("step 3 of 5 done: schema updated. Next: backfill the column").
- Cap lists at 5 items. Past five, split into do-now and later.
- Give time estimates in concrete units ("15 minutes if tests cover this, an afternoon if not").
- Show finished work concretely: what now works, and how to see it.
- State errors matter-of-factly — cause, then fix. Never "uh oh".
- Finish one thing before you raise the next. Surface the rest once, at the end.
- End with one concrete next action that the developer can do in under two minutes.

Before you send, delete: opening sentences that announce what you will do, closing recaps, "anything else?", sidebars, hedging adverbs, and idioms.

Then check: from the first line and the last line only, is the next action clear?

The shape yields only when it would delete the answer. "Explain this" gets a full explanation with headers. "What are my options" gets 2–4 ranked options, recommendation first. Safety outranks brevity: confirm before destructive actions. After three turns of "still broken", stop editing code and name the assumption that may be wrong.

If the developer says "normal mode", drop this section for the session and confirm in one line.

## MANDATORY — Writing style (ASD-STE100)

Write all output in Simplified Technical English. This applies to every agent, every report, every commit message, and every document.

- Use the active voice.
- Start each instruction with the command verb. One instruction per sentence.
- Keep instructions to 20 words or fewer. Keep descriptive sentences to 25 words or fewer.
- Keep one topic per paragraph.
- Use one term for one thing throughout.
- Use no more than three stacked nouns. Keep the articles.
- Put the warning before the instruction it applies to.

## MANDATORY — User-facing UI copy

State what the feature does, what the user must provide, and limitations that
affect behavior or decisions. Keep implementation notes, protocol distinctions,
internal terminology, and developer-facing caveats in documentation, code
comments, API references, or developer tooling. Use technical language only when
the target user needs it to configure, diagnose, or understand the product;
remove non-actionable contrasts such as "not X" or "internally Y".

## MANDATORY — Do no useless work

Do work that changes what the product does, or what a person can do with it. Stop work that only creates the appearance of rigour.

Never write a test that asserts on prose. A test that greps a Markdown file, an AGENTS.md phrase, or a comment tests nothing. It fails when someone improves the wording, and it passes while the described behaviour is broken. Delete such a test on sight.

Test behaviour through the interface a caller uses. Ask one question first: which user-visible behaviour breaks if this test disappears? If you have no answer, do not write the test.

Do not add these:

- A test that asserts a document contains a string, a heading, or a section order.
- A test that restates a constant, or that asserts source text matches a copy of itself.
- A test for a branch no caller can reach.
- A scorecard, an audit table, or a metric that nobody acts on.
- A summary document about work you already did.

Prefer one real check over five proxy checks. When you find yourself adding a guard because a document might drift, write the document once and stop.

State a blocker plainly. Do not fill the gap with adjacent busywork.

## SDKs

All three first-party SDKs live in this repository, one clone and one worktree
with the product:

| Directory | Package | Registry | Release tag |
| --- | --- | --- | --- |
| `sdks/elixir` | `postdeploy_sdk` | Hex | `elixir-v<version>` |
| `sdks/javascript` | `@postdeploy/sdk` | npm | `js-v<version>` |
| `sdks/ruby` | `postdeploy` | RubyGems | `ruby-v<version>` |

The pre-rebrand names `@alplus/sdk`, `alplus_sdk` and `alplus-ruby` are
retired; see `docs/POSTDEPLOY_REBRAND.md`.

`sdks/contract` holds the golden wire fixtures the product owns. Each SDK pins
the contract version and every digest in its own code and reads that directory
from this checkout, so `mix test`, `npm test` and `bundle exec rspec` work in a
fresh clone with nothing set up. `POSTDEPLOY_CONTRACT_DIR` overrides the
location.

CI is path-filtered: a change under one SDK runs that SDK's workflow alone; a
change under `sdks/contract` runs the product suite (which contains the server
parser anchor) and all three SDK suites. That is the compatibility gate — there
is no separate cross-repository workflow.

To release one SDK: bump its manifest version, merge, then push its namespaced
tag. The release workflow refuses to publish when the tag and the manifest
disagree. Nothing else publishes; a product change can never publish an SDK.

The product still consumes the Elixir SDK as the released Hex package
(`mix.exs`, `only: :test`) rather than a path dependency, so the end-to-end
ingest test drives the same bytes third parties install.

The three SDKs previously lived in `Alplus-Tech/sdk-js`, `-elixir` and `-ruby`;
those repositories are archived and their history is in this one. Phoenix
assets use the `tailwind` and `esbuild` Mix wrappers, not npm — `npm` here
belongs to `sdks/javascript` only. Docs (`docs/ARCHITECTURE.md`,
`docs/BUILD.md`) still cite old paths as historical migration context.

## Hard rules

1. Warning: `postdeploy.dev` serves the Elixir stack from `master` since 2026-08-20. A deploy reaches real users. The old Cloudflare stack is retained, no longer routed, and exists only as the DNS rollback. Do not deploy it, write to its databases, or change its secrets without an explicit founder instruction in the current conversation.
2. Scope every tenant query by org/project. Return 404 for cross-tenant ids, never 403.
3. Get founder approval before any new production dependency.
4. Write Conventional Commits with the why.
5. Ship tests in the same change. Test behaviour through a caller's interface. Never assert on prose. Keep the suite fast. No browser E2E.
6. Never render a middot (`·`) or a dash (`—`, `–`) as a separator in UI text or user-facing copy. Separate values with a comma, a slash, parentheses, or distinct elements or lines.
7. Warning: the public repository `abpaul/postdeploy` receives snapshots only. Never push a branch or a commit of the canonical repository to it. Follow `docs/PUBLIC-MIRROR.md` (private) and get founder approval for each push.

## Hard-won lessons

Generic, reusable notes from real work in this repo. Read before a large change.

- **Run an independent adversarial reviewer after any large or security-sensitive change.** A green suite is not proof. Five build agents and 729 passing tests still shipped a cross-tenant hole; the review caught it. Use the `reviewer` agent, prompted to disagree, and budget a review pass into the scope.
- **Mirror the canonical tenant policy on every new resource.** Scope each action by `org_id` AND `project_id` AND membership, exactly like `Alplus.Monitoring.Monitor`. A read failure must filter the row (404), never 403. Copy Monitor's policy block; do not hand-roll a subset. Tightening a policy ripples to callers and fixtures, so expect to project-scope their actors.
- **A raw `Repo.query!` returns a `NaiveDateTime` for a timestamp column, not a `DateTime`.** `DateTime.diff/3` and similar crash on a naive value. Coerce at the boundary with `DateTime.from_naive!(value, "Etc/UTC")`. This bug appeared twice.
- **Verify effects, not acknowledgements.** A 204, 202, or `:ok` routinely means nothing happened: Measure drops a beacon for a non-allow-listed domain; a monitor seeded in a throwaway `mix run` BEAM never registers with the running scheduler. Query the actual row.
- **The default Tailwind palette is wiped.** An invented token name renders invisible. Use only the real tokens in `docs/DESIGN-SYSTEM.md`. There is no `-solid` variant.
- **Deploy is Kamal, and it has sharp edges.** Run it with a UTF-8 locale (`LANG`/`LC_ALL`, `RUBYOPT=-Eutf-8`) or it crashes on non-ASCII SSH output. Run from the main repo, not a git worktree, so `tofu output` resolves `DATABASE_URL`. Migrations and content seeding both run on container boot, so a failed migration crashes the container and the old release keeps serving (no outage). AWS SSO expires mid-session; re-auth with `aws login`.
- **A third-party-embedded script must post to an absolute endpoint.** A served `m.js` that used a relative `/m` posted to the host page's origin, not ours. Derive the endpoint from the script's own `src`. Cloudflare edge-caches `/m.js` for hours, so a code fix needs a cache-bust or a purge to reach visitors.
- **Sequence dependent multi-agent work; do not run parallel agents on one working tree.** Concurrent edits to the same files collide. Use a pipeline (or isolated worktrees) when phases share files, and self-verify (`mix format`, `mix compile --warnings-as-errors`, `mix test`) at each phase boundary.
- **A green `/health` is not evidence a host can take traffic.** A migrated-but-unseeded database served `ok` from `/health` and a homepage (via `PageController.home/2`'s deliberate fallback) while every content-backed page 404'd. Before pointing DNS anywhere, run `scripts/verify-cutover.sh`: it proves the candidate serves every URL the live sitemap already lists. `docs/PRODUCTION-CUTOVER.md` opens with the full trap list; read it before any deploy.
- **Migrations and seeds need opposite failure policies.** The boot chain is `migrate() && seed() && exec start`. A failed migration must exit non-zero and stop the chain; a failed seed must log and exit 0, because the console and ingest work without content rows and crashing over a marketing page takes the product down with it. Verified by exit code, not by reading.
- **`PHX_HOST` must be the hostname users type.** Phoenix's default `check_origin: true` compares every LiveView websocket Origin against the endpoint's `url:` host, which comes from `PHX_HOST`. A mismatch renders every marketing page perfectly and silently breaks the console, so it is invisible until someone signs in. Marketing URLs are unaffected: `Marketing.Seo` pins the origin and `m.js` derives its endpoint from its own `src`.
- **Developer tooling belongs in `dev/`, never `lib/`.** A module in `lib/` compiles into the production release. `Alplus.Seo.Audit` uses `lazy_html` (a `[:dev, :test]` dep), so living in `lib/` produced "module LazyHTML is not available" warnings and shipped a module that would raise if called. `elixirc_paths` puts `dev/` in `:dev` and `:test` only.
- **Validate a release locally before deploying.** `MIX_ENV=prod mix release` then run the Dockerfile CMD chain by hand with `DATABASE_SSL=false` (local Postgres has no TLS; RDS requires it). The full env recipe is in `docs/PRODUCTION-CUTOVER.md`. A missing variable raises by name at boot, which is the fastest way to learn what a new setting needs.
- **Accepted is not delivered, and delivered is not read.** Cloudflare SMTP answered `{:ok, "2.0.0 Ok <id@postdeploy.dev>"}` for a password reset the recipient never saw. Three facts need three pieces of evidence: the relay accepted it (the `deliver` return value), it reached the mailbox (the receiver, or a Cloudflare Email Sending log lookup by message id), and it landed in the inbox rather than Junk (only the recipient knows). Send a text part alongside the HTML: a single-link HTML-only body is a strong spam signal, and iCloud discards such mail from a domain with no sending history without bouncing. Publish DMARC with `rua=` or receiver verdicts stay invisible.
- **Match the runner architecture to the target architecture.** `config/deploy.yml` builds `arch: arm64` for an arm64 host, so `runs-on: ubuntu-latest` compiled the whole Elixir toolchain under QEMU. That was invisible while the deps layer stayed cached and cost 42m52s the moment a dependency bump invalidated it. `runs-on: ubuntu-24.04-arm` made the same deploy 1m25s; `scripts/deploy-local.sh` does it in 59s natively. When switching, fix every architecture-specific download too: the x86 `session-manager-plugin.deb` will not install.
- **A one-way subtree mirror goes stale silently, and registries are immutable.** The SDK mirrors were six days behind when their first release was cut, and one lacked the `README` and `LICENSE` its own package manifest listed. Publish only from the canonical repository. Registries differ: RubyGems supports a pending trusted publisher, so a brand-new gem ships over OIDC with no secret, while Hex has none as of 2.5.1 and needs a write-scoped `HEX_API_KEY`.
- **A Workers Custom Domain owns its DNS record.** Adding a Cloudflare Tunnel public hostname for a host the old Workers stack served fails with "A DNS record managed by Workers already exists on that host." Remove the Custom Domain first, and delete any route pattern matching that host: a Workers route wins at the edge whatever DNS says, so one left behind keeps the old stack serving after the cutover.
- **A placeholder credential is indistinguishable from a working one.** Production ran Cloudflare Turnstile's testing keys for weeks: `1x00000000000000000000AA` renders a widget stamped "For testing only", and its secret validates every response token, so sign-up worked, looked healthy, and had no bot protection at all. A missing key fails loudly; a test key fails silently. `config/runtime.exs` now refuses to boot on one (`Alplus.Turnstile.dummy_key?/1`). Apply the same reasoning to any vendor's sandbox credential.
- **A default that names infrastructure needs a check that resolves it.** All three published SDKs default to `https://ingest.postdeploy.dev`. That hostname had no DNS record, so every third-party install posted into the void with no error the developer could act on, and no unit test could ever catch it: the bug was in DNS and edge routing, not in code. `scripts/acceptance-smoke.sh` now asserts the host answers `/health` and returns 401 for an unkeyed post.
- **Check capacity and permission where a human can act, not where the write happens.** Two bugs, one shape. An invitation was created and emailed on a one-seat plan, then refused in the recipient's browser as "Could not accept that invitation." — the seat check lived on membership creation. And a monitor row that never reached the scheduler stayed `active` in the console while checking nothing, because registration depended on someone calling `reconcile_monitor/1` rather than on a converging loop. Move the check to the earliest point where the person who sees the error can fix it, and let the database be the thing that decides.

- **A `*path` route also matches zero segments.** It silently swallowed the shorter sibling route declared after it. Declare the shorter route first, or use explicit segments.
- **Ash ANDs every applicable policy block.** A new `policy` block never grants access; it adds another condition. Scope public actors to a dedicated action.
- **Read the row before you replay or rotate a credential.** A handover asked to replay `measure.create_source` through the idempotency cache to recover a lost Measure browser token. The token is public and stored in the clear on the Source row (`measure_token`, ADR 0001), so one read-only RPC answered it. The handover also said the original call came from the dashboard; the record carried an OAuth `grant_id`, and the identity includes it, so the proposed replay would have missed the cache and created a second source. See `docs/runbooks/production-rpc.md`.
- **A permission deny rule matches command arguments, not only file reads.** `Read(~/.ssh/**)` denied every `ssh -i ~/.ssh/alplus_ed25519` even with `Bash(ssh:*)` allowed. Drop the `-i` flag; the default key works. The denial looks like a random classifier refusal until you compare the allowed and denied commands.

## V3 redesign notes

Facts that are cheap to state and expensive to rediscover. Each one cost a real
debugging round during the V3 redesign.

### Repository layout

- **The git repository root is `elixir/`, not the parent `AL+/`.** `git` from
  `AL+/` fails with "not a git repository".
- `AL+/DESIGN.md` is a **symlink** to `elixir/DESIGN.md`. Edit the tracked file.
- `AL+/PRODUCT.md` and `AL+/AGENTS.md` sit above the git root and are not
  versioned with this code.
- Code comments still cite `docs/DESIGN-SYSTEM.md` by section number. Those
  sections now live in `DESIGN.md`'s implementation appendix.

### Design authority, in precedence order

1. `designSystem/PostDeploy v3.dc.html`, the visual authority. Every hex, size,
   radius and spacing decision originates there. See `designSystem/AGENTS.md`
   first: its screen specimens are drawn inside a documentation frame that is
   not part of the product, and two agents shipped that frame as chrome.
2. `DESIGN.md`, how those decisions are expressed here.
3. The code.

When 1 and 2 disagree the visual spec wins, **and you record the resolution in
`DESIGN.md`** so nobody re-litigates it. Already settled: chart annotations
inside the plot may go to 10-11px against the 12px floor; sections `05` and `12`
draw no first-run state at all, so `DESIGN.md`'s first-run recipe is additive and
the only dashed frame the spec draws stays the small in-panel slot; the selected-tab
underline shape is shared and the arm picks the brand value; chips follow the
12px floor rather than the mock's 11-11.5px, because a chip carries standalone
meaning outside any plot and the exception list covers in-plot annotations only.

### Product rules that look like bugs

- **The dashboard is read-only by design.** Create, configure and destroy happen
  through MCP. A missing "New ..." button is usually deliberate.
- **The human-only exceptions are organization, team membership, and plan or
  billing changes.** "Invite a teammate" is correct. Check `PRODUCT.md`
  before you delete a create affordance.
- **A project can now be created from either side** (founder decision
  2026-09-20). The console keeps "New project", and `projects.create` gives
  an agent the same ability, so an agent setting up a new service creates the
  project and then fills it. The tool needs `projects:write` and an
  organization-scoped grant; a project-pinned grant is refused, because its
  consent named one project.

### Tests

- The baseline for `mix test test/alplus_web` is **999/999 passing** (2026-08-28).
  If you see fewer, compare against `master` before you assume you caused it.
- `ErrorIngestControllerTest`'s "fans out a quota alert" test **flakes**, and
  passes on rerun and in isolation. It is not a regression.
- **When two test files assert contradictory contracts, do not choose by taste.**
  Run `git log --format='%ad %h %s' --date=format:'%m-%d %H:%M' -- <file>` on
  both. The later deliberate commit wins; update the stale file.
  `PageControllerTest` and `HomeLiveTest` disagreed about the homepage switches,
  and ten tests stayed red on `master` because nobody checked.

### Phoenix and LiveView

- **HEEx escapes interpolated strings.** `{"Couldn't load"}` renders
  `Couldn&#39;t load` and fails a literal assertion. Keep literal copy as a text
  node; interpolate only dynamic values.
- `/reset` shares `SignInLive`'s `:sign_in` live_session with `/sign-in`. An
  `on_mount` hook must branch on `socket.assigns.live_action`.
- `/` is `HomeLive`, a LiveView, although `PageControllerTest` exercises it over
  plain `GET`.
- Homepage switches are **deliberately** buttons that do not write to the URL
  (`aec64640`), while the URL still seeds the projection on mount. Selection is
  `aria-pressed`, not `aria-current`.

### Seeding for visual verification

- Observe issues cannot be created with `Ash.Seed.seed!`; the resource raises a
  misleading multi-constraint error. Use the `:record` action.
- Changelog entries need `Ash.Seed.seed!` with a synthetic `grant_id`, which
  makes the Changelog screen show a "not connected" notice above a populated
  table. That is a seeding artefact, not a defect.
- Charts read `:error` only on genuine misconfiguration, never on missing
  rollups. "Couldn't load this chart" across a seeded environment means the seed
  omitted a valid interval or window.
- Delete any seed script you add before you finish.
