# User-facing UI copy

State what the feature does, what the user must provide, and limitations that affect behavior or decisions. Keep implementation notes, protocol distinctions, internal terminology, and developer-facing caveats in documentation, code comments, API references, or developer tooling. Use technical language only when the target user needs it to configure, diagnose, or understand the product; remove non-actionable contrasts such as “not X” or “internally Y.”
